# LedgerQuest 交互与游戏设计规格

> 版本：v0.1  
> 日期：2026-11-20  
> 适用范围：`LedgerQuest.html` 单文件版本及后续内容包  
> 文档性质：交互、状态、信息层级与内容节奏规范；不包含页面实现代码

## 0. 一句话结论

LedgerQuest 不是“把中级会计题装进剧情”，而是让柚柚在一次次具体工作场景里完成**找关键词 → 翻译题意 → 做一个判断 → 看因果解释 → 处理同类问题**。每一关只承担一个学习动作，答错必须是有信息量的诊断，不能只是换一句随机安慰。

实现优先级：

- **P0：先做对学习闭环。** 六种题型的作答契约、完整答题状态流、顺序解锁、固定三件套、二次答错脚手架、移动端可用性、详解与焦点管理、内容校验。
- **P1：再做游戏感。** 章节冷开场/收尾、连击与靠谱值、踩坑记录、针对性错因文案、可选音效、复盘页。
- **P2：最后加彩。** 更丰富的角色演出、章末印章、跨科联动关卡和装饰性动效。

## 1. 体验目标与边界

### 1.1 玩家真正要做的事

玩家不是来证明自己会不会，而是来训练三种能力：

1. 从题干中识别决定会计处理的词。
2. 把准则语言翻译成一个可执行的判断或计算。
3. 在相近概念之间说清“为什么是它，不是另一个”。

因此，答题结果只占体验的一半；**关键词如何影响判断、错误选项错在哪、分录为什么这样写**才是主体。

### 1.2 成功标准

- 新玩家进入第一关后，30 秒内能说出“这题要我干什么”。
- 任何一关都能在 60–180 秒内完成一次完整学习循环，不靠计时制造紧张。
- 答错一次后，玩家知道下一步应该检查什么；答错两次后，必须获得可执行的拆解路线。
- 任何玩家都不会被一道题永久卡死；可以选择自己再做一次，也可以沿详解带练通过。
- 手机 375px 宽度无横向滚动，主要按钮触控高度不小于 44px。
- 只用键盘也能完成选择、输入、提交、重试、打开/关闭详解和进入下一关。
- 关闭动效或音效后，学习信息不丢失，状态变化仍有文字反馈。

### 1.3 明确不做

- 不做限时闯关、倒计时压迫或“答错扣命”。
- 不做排行榜、公开错题展示或社交攀比。
- 不把“连击”做成解锁条件，避免玩家为了保连击而不敢学习。
- 不用纯记忆题填充体量；每个关卡都要能回答“这个知识点解决什么工作问题”。
- 不依赖外部字体、图片、音频、CDN 或网络请求。

## 2. 核心游戏循环

### 2.1 单关循环

```text
进入工作现场
  → 看 1–2 句剧情冲突
  → 读固定三件套：关键词 / 这题要你干什么 / 题干翻译
  → 在原题中核对数字与条件
  → 选择、输入、排序或圈词
  → 提交
  → 答对：看判断链 + 剧情推进 + 解锁
  → 答错：看针对性错因 + 重试 / 详解 / 二次脚手架
  → 进入同章下一关或回看
```

一关对应一个“可命名的工作动作”，例如：

- 判断这笔支出是否进入存货成本。
- 算出本期应转回的跌价准备。
- 选出与业务实质匹配的会计分录。
- 把收入确认五步法恢复成正确顺序。
- 圈出决定研发支出能否资本化的词。
- 判断“谨慎性就是压低利润”这句话对不对，并选出理由。

### 2.2 一个学习节的节奏

建议以“章节”为一次学习节，而不是以整科为单位：

| 节拍 | 内容 | 时长建议 |
|---|---|---:|
| 冷开场 | 王姐或现场 NPC 抛出一个具体麻烦 | 20–40 秒 |
| 2–3 个教学关 | 正常案例，先建立规则 | 每关 1–3 分钟 |
| 1 个换皮关 | 同一规则换业务、换数字或换科目表述 | 1–2 分钟 |
| 1 个迁移关 | 放到三科交叉或易混情境中 | 1–3 分钟 |
| 章末复盘 | 用“抓对什么 / 还需回看什么 / 下章预告”收尾 | 30–60 秒 |

连续 3 关不得使用同一题型；同一章节中，判断题占比不超过 20%，数字计算不超过 30%。如果章节内容不足 4 关，至少保证题型有变化，并缩短章节，不硬凑。

### 2.3 关卡之间的连接

- 答对后剧情必须有一句“业务结果”，不能只弹“正确”。
- 答错不改变剧情走向，但可以增加一句角色反应，表现“现场还在等你把账做对”。
- 每章最后一关结束后进入**章末复盘**，不要直接跳回地图。
- 知识库始终开放；主线锁定只限制“闯关”，不限制“查知识”。

## 3. 六种关卡类型

### 3.1 总原则

- 每种题型都只考一个核心判断，不把阅读、计算、分录三个难点叠在同一关。
- 所有答案用稳定 ID 表示，不依赖选项数组位置；渲染时可以安全重排。
- 错误选项必须能映射到一个具体误解，不能只是“看起来不对”。
- 提交前允许修改；提交后锁定当前答案，直到重试或进入下一状态。
- “答对”只表示当前答案正确，不等于已经理解；正确反馈仍要展示判断链。

### 3.2 题型规格

| 题型 | 玩家动作 | 适用场景 | 防“蒙对/刷题”规则 | 核心反馈 |
|---|---|---|---|---|
| 情景选择 `choice` | 从 3–4 个选项中选 1 个 | 规则边界、科目归属、计量属性、税务处理 | 干扰项都必须是常见误解，且用相近措辞；选项顺序固定，避免每次洗牌造成记忆位置 | 指出正确项的依据，并单独解释玩家所选干扰项的误区 |
| 数字计算 `number` | 输入数字，单位固定在输入框后方 | 入账成本、跌价准备、折旧、暂时性差异、补价比例 | 一关只做一条主公式；可接受千分位与有限小数误差；不能靠选项反推 | 展示“取数 → 运算 → 结论”的 2–4 步计算链 |
| 分录判断 `journal` | 从多张凭证中选 1 张 | 初始计量、折旧、收入确认、政府补助、债务重组 | 至少有一张“借贷也平，但科目或方向错”的干扰凭证；金额差异必须来自本题条件 | 逐行对照借贷方向、科目、金额，说明整张凭证为何成立 |
| 步骤排序 `order` | 点选 3–6 个步骤，形成顺序；再次点击取消 | 收入五步法、减值分摊、合并抵销、会计处理流程 | 每次进入必须打乱展示顺序；正确顺序不能恰好等于初始顺序；不得拖拽唯一操作方式 | 标出第一个错位步骤，再给出整条流程的逻辑锚点 |
| 找关键词 `keyword` | 从 6–9 个词块中选 2–4 个“决定处理方法的词” | 资本化条件、控制权转移、租赁豁免、会计变更判断 | 必须有近义词或看似相关但不会改变结论的干扰词；只接受集合，不接受自由文本 | 逐个解释“为什么它改变判断 / 为什么它只是背景信息” |
| 判断题 `boolean` | 先选“对/错”，再选 1 个理由 | 易混结论、准则口径、常见绝对化说法 | 不能只有二选一；理由 chip 必须与判断配套，防止 50% 蒙对；不使用“以上都对”类选项 | 同时指出判断正误和理由正误；错误理由要显示其偷换了什么条件 |

### 3.3 各题型的交互细则

**情景选择**

- 选项使用 A/B/C/D 字母键位，但字母只是辅助，不进入题干正文。
- 支持按 `1–4` 选对应选项；数字键输入数字题时不启用选项快捷键。
- 选中后显示明确勾选标记，不能只靠浅绿色底色。

**数字计算**

- 使用 `inputmode="decimal"`，允许千分位，提交前自动去空格和逗号。
- 单位固定展示，玩家只填数值；题干出现“万元/元”时，单位框必须与答案口径一致。
- 答案容差默认 `0.01`，整数题也可配置为 0；负数允许输入。
- 输入为空、只输入符号或无法解析时只提示格式，不增加答错次数。
- 不显示“正确选项”或“答案就在附近”的暗示。

**分录判断**

- 每张凭证按“借/贷 → 科目 → 金额”三列呈现；金额一律带千分位。
- 选中整张凭证，不做逐行拖拽；后续如要进阶，可增加“指出错行”，但不作为首版 P0。
- 正确反馈先解释业务，再落到分录；错误反馈只在玩家所选凭证内部标出可疑行，不直接替玩家改账。

**步骤排序**

- 初始顺序打乱，且必须满足“至少 2 个步骤不在正确顺位”。
- 点击加入顺序，再次点击取消；右侧或下方显示 `已选 2/5`。
- 提供“清空重排”，不要求玩家逐个撤回。
- 键盘操作提供“上移/下移”按钮，不能只有拖拽。

**找关键词**

- 词块必须来自题干或可直接对应题干的短语，避免脱离语境猜术语。
- 选中词块后高亮，并在原题中出现同词高亮；若原题没有该词，需明确它是“隐含条件”。
- 正确集合建议 2–3 个，最多 4 个；答错时先不公布完整答案，只指出“多选了一个背景词”或“漏掉了决定口径的词”。

**判断题**

- 主问题是“这句话对不对”，第二步是“因为什么”。
- 只有判断正确、理由也正确才算本关通过。
- 若判断正确、理由错误，文案必须承认“方向对了”，再纠正依据，避免把玩家整体判为不会。

### 3.4 题型与内容的搭配限制

- 相同知识点最多允许 2 个关卡：一个建立规则，一个换皮迁移。
- 不以“同一道题改数字”作为新关卡。
- 一道题如果需要两条以上公式，拆成两个关卡。
- 分录题必须附业务说明，不让玩家只凭科目名称猜答案。
- 判断题只用于真正容易绝对化的结论，不拿来凑数量。

## 4. 答题状态流

### 4.1 状态定义

页面路由与关卡状态分开管理：

- 页面路由：`home / map / level / library / archive`。
- 关卡状态：`first_read / answering / wrong_1 / wrong_2 / correct / guided / review`。
- 详情弹层是叠加状态，不替换关卡状态。关闭详情后必须回到原位置、原答题状态。
- 章节结束使用 `chapter_recap` 状态，不能只弹一条 Toast。

每个关卡至少维护以下状态：

| 状态 | 含义 |
|---|---|
| `attempts` | 已提交且判错的次数；格式错误不算 |
| `coachLevel` | 0 无辅导、1 一次错因提示、2 完整拆解 |
| `draft` | 当前未提交的选择、数字、排序或词块集合 |
| `lastSubmitted` | 最近一次已提交答案，用于回显错选项 |
| `assisted` | 是否在作答前查看了会直接揭示答案路径的详解 |
| `detailOpen` | 是否正在看详解；不改变 `attempts` |
| `completionKind` | `clean / assisted / self_corrected / guided` |
| `isReview` | 是否复玩已通关关卡 |

### 4.2 主状态流

| 当前状态 | 触发 | 新状态 | 页面与系统动作 |
|---|---|---|---|
| 未进入 | 从地图点开已解锁关卡 | `first_read` | 写入“最近学习位置”，展示剧情和三件套；不复用上一次答案 |
| `first_read` | 开始操作 | `answering` | 草稿可编辑；提交按钮在答案完整前禁用 |
| `answering` | 提交且格式不完整 | `answering` | 只提示“还差一个选项/还差 2 个步骤”，不计错 |
| `answering` | 提交且正确，首次通关 | `correct` | 记录 `clean / assisted / self_corrected`；计算靠谱值；立即解锁下一关；显示判断链和剧情结果 |
| `answering` | 第一次提交错误 | `wrong_1` | `attempts=1`、`coachLevel=1`；清零连击；记录踩坑；显示本题专属错因 |
| `wrong_1` | 点“带着提示再试” | `answering` | 清空草稿，但保留 `coachLevel=1` 和一条紧凑提示；不重置错题次数 |
| `wrong_1` | 点“我先看详解” | `wrong_1 + detail` | 打开详解；不增加次数、不自动解锁 |
| `answering` | 第二次提交错误 | `wrong_2` | `attempts=2`、`coachLevel=2`；自动展开“拆解路线”，不直接给最终答案 |
| `wrong_2` | 点“再试一次” | `answering` | 清空草稿；保留完整拆解；玩家可继续独立作答 |
| `wrong_2` | 点“看详解” | `wrong_2 + detail` | 详解先给一句话结论，再给步骤、例证、分录和坑点 |
| `any` | 点“按解析带练通过” | `guided` | 仅二次答错后开放；记录 `guided`；按 20% 基础靠谱值结算；解锁下一关；显示“这次是带练，可回看补做” |
| `correct` | 点“继续下一关” | 下一关 `first_read` | 当前关保持已通关；进入同章下一关 |
| 章末 `correct/guided` | 点“本章收工” | `chapter_recap` | 展示抓对的规律、最值得回看的坑、剧情收尾与下章入口 |
| 已通关关卡 | 再次进入 | `review` | 显示“复习模式”；不重复发靠谱值；可重置答案再练 |

### 4.3 答对

答对后不要立刻自动跳关。顺序必须是：

1. 锁定答案，显示正确态。
2. 播放一次很短的确认动效或文字落印。
3. 先给一句**结果判断**，再给判断链。
4. 显示参考答案、公式/分录和剧情推进。
5. 主按钮变为“继续下一关”；章末则变为“本章收工”。

系统在判定正确时立即写入通关记录并解锁下一关，但玩家必须自己点击按钮才前进，防止误触跳过反馈。

### 4.4 答错一次

第一次错误只做三件事：

- 指出这次答案“错在哪个判断点”。
- 给一条能改变下一步的提示，不公布正确答案。
- 给三个动作：`带着提示再试`、`我先看详解`、`返回地图`。

错误反馈必须绑定到玩家所选项或所填数值。没有具体误解数据时，才退回通用提示；不能把随机安慰句当作主要反馈。

### 4.5 答错两次

第二次错误不继续堆更多红色警告，而是切换到“拆解模式”：

- 自动展开题干翻译，虽然三件套本来就常驻。
- 展示 2–4 步判断路线，只填空位或标出第一个关键分叉，不直接展示正确选项。
- 显示相关易混点，例如“可抵扣增值税是否进入成本”。
- 主操作仍是“再试一次”，让玩家保留自主完成的机会。
- 次操作是“看详解”；详解底部提供“按解析带练通过”。

二次答错后的目标是降低认知负荷，不是降低到“看一眼答案就算学会”。因此带练出口必须同时展示：

- 正确结论。
- 关键取数/分录。
- 玩家原错误与正确路径的分叉点。

### 4.6 查看详解

- 任意时刻可打开，不消耗答题次数，不改变答题状态。
- 打开时把焦点移入详情，关闭后焦点返回触发按钮。
- 详情不能覆盖当前草稿；关闭后仍保留已选答案。
- 若详解包含当前关答案，页面标记 `assisted=true`。该标记不阻止通过，但会取消连击，并将本次靠谱值上限降至 60%。
- 固定三件套与题干翻译是学习支架，不算“看答案”，不影响奖励。

### 4.7 重试

- 重试只清空 `draft` 和错误高亮，不清空 `attempts`、`coachLevel` 和踩坑记录。
- 第一次重试保留一条方向提示；第二次重试保留完整拆解。
- 排序题重试可以恢复同一打乱顺序，避免玩家靠重开刷出简单顺序。
- 数字题重试清空输入框并自动聚焦，不把上次错误数字留在框中。

### 4.8 解锁

- 当前关答对或带练通过后，立即解锁同章下一关。
- 本章全部关卡以任一有效方式通过后，解锁下一章第一关；知识库同步可查新章节。
- 三科之间不互相硬锁；每科第一章默认开放。
- 连击、靠谱值、查看详解都不能代替通关条件。
- 已完成关卡可随时复习，但复习不重复发靠谱值。
- 地图和路线图必须区分 `锁定 / 可进入 / 进行中 / 已通关 / 带练通过`，不能只靠颜色。

### 4.9 离开与恢复

- 每次提交后立即持久化答题结果和踩坑记录。
- 未提交草稿只在当前页面会话内保留；刷新后回到该关开头，不泄露答案。
- 已通关状态、`completionKind`、连击、靠谱值和踩坑记录使用本地存储。
- 旧版本只有布尔通关记录时，迁移为“已通关，通过方式未知”，不要清空进度。
- 锁定章节可以被查看简介，但不能直接开始关卡；知识库不受此限制。

## 5. 低阅读负担的信息层级

### 5.1 固定三件套

每一关默认阅读路径中必须同时出现以下三块，且不得折叠：

1. **关键词**：2–4 个，来自题干的条件词。
2. **这题要你干什么**：一句话说明动作、对象和产出。
3. **题干翻译**：把准则语言还原成业务白话，不使用新的术语。

这里的“固定展示”指**常驻默认阅读路径**，不是三块都做成 sticky 浮层。桌面端可放在主栏上方，手机端按顺序纵向排列。

### 5.2 推荐顺序

```text
关卡标题 / 第 3 关，共 5 关
剧情冲突（1–2 句）
关键词 chips
这题要你干什么（任务句）
原题（最多 3 处关键高亮）
题干翻译（常驻，和原题紧邻）
作答区
提交 / 重试
反馈
详解入口
```

先看任务再读原题，是为了给玩家一个“读题锚点”；翻译紧跟原题，避免玩家看完白话后还要回头找原句。

### 5.3 文案预算

| 元素 | 建议上限 | 写法要求 |
|---|---:|---|
| 关卡标题 | 16 个汉字 | 是可判断的知识点，不写章节空话 |
| 剧情冲突 | 2 句 / 70 字 | 第一句交代现场，第二句提出麻烦 |
| 关键词 | 2–4 个 | 每个 2–8 字；必须出现在题干或能明确对应隐含条件 |
| 任务句 | 36 字 | 以动词开头：判断、算出、选出、排序、圈出、核对 |
| 原题 | 120 字 | 数字、单位、条件尽量分行或分组 |
| 题干翻译 | 55 字 | 一句话翻译业务实质，不重复整道题 |
| 正确结论 | 1–2 句 | 先说结论，再说为什么 |
| 主反馈解释 | 80–140 字 | 只讲本关判断链 |
| 错因提示 | 1–2 句 | 必须指向具体词或具体误算 |
| 易错点 | 每条 35 字 | 解释“为什么会混”，不只写“注意区分” |

### 5.4 视觉层级

- 关卡标题是最大文字；任务句是第二层级；原题正文不得比任务句更弱。
- 关键词使用黄色或浅暖色标记，但同一屏最多两种高亮色。
- 正确态以绿色对勾和文字双重表达；错误态以珊瑚色图标和文字双重表达，不能只用红绿。
- 正文最小 14px，辅助文字最小 12px；当前骨架大量 9–11px 的文案需要上调。
- 中文正文每行建议 26–38 字；桌面主栏不要铺满整个窗口。
- 题干中的数字、时间、主体和“通常/应当/不包括”等条件词按语义高亮，不把所有关键词重复高亮到满屏。

### 5.5 详解层级

详解首屏先回答“这关到底在考什么”，再展开：

1. 一句话结论。
2. 什么时候用 / 怎么判断。
3. 2–4 步操作路径。
4. 一个同类小例子。
5. 对应分录或公式。
6. 易错点。
7. 相邻知识点。

首屏不应直接出现长篇准则原文。分录在手机端横向展示时，科目列优先，金额列靠右且允许换行。

## 6. 布局、动效、音效与可访问性

### 6.1 桌面端

适用宽度：`>= 1024px`。

- 内容最大宽度建议 1160–1240px，关卡主栏 720–820px，右侧辅栏 280–318px。
- 主栏承载剧情、三件套、原题、作答和反馈；反馈保持在文档流内，不用全屏弹窗打断上下文。
- 右栏只放两层信息：本关路线、当前可用的帮助入口。不要同时塞统计、广告式提示和多张卡片。
- 顶栏的靠谱值和连击在关卡页可显示，但不抢主按钮视觉权重。
- 详解使用右侧抽屉或居中弹层；打开后背景内容保持位置，不重新渲染主页面。

### 6.2 手机端

适用宽度：`<= 820px` 单栏；`<= 560px` 进入紧凑模式。

- 顶栏压缩为“品牌 / 当前进度 / 更多”；科目导航不在关卡页重复出现。
- 剧情卡在三件套上方，默认显示 2 句；不再额外放角色装饰占半屏。
- 关键词、任务、翻译按固定顺序纵向排列，三块之间用清晰标签和留白分隔。
- 作答控件全宽，选项最小高度 48px；排序支持点选和上下移动，不依赖拖拽。
- 提交、重试、继续下一关使用底部操作条，并留出 `safe-area-inset-bottom`。
- 右栏路线折叠为“3/5 关卡”按钮，点开底部抽屉；不把整条路线堆在题目后面。
- 题目反馈出现在作答区下方，同时把焦点或阅读起点移动到反馈标题；不要只靠 Toast 告知。
- 手机首屏至少露出“关键词、任务、原题开头”，不能先连续展示三张装饰卡。

### 6.3 动效

| 场景 | 动效 | 时长 | 限制 |
|---|---|---:|---|
| 页面/关卡进入 | 12px 上浮渐入 | 220–280ms | 只播一次 |
| 选择答案 | 边框收紧 + 勾选印章 | 120–180ms | 不缩放文字 |
| 答对 | 小印章落定 + 轻量彩纸 | 400–600ms | 彩纸不超过 12 片 |
| 答错 | 仅错误项轻震 1 次 + 提示框展开 | 160–220ms | 不整页抖动 |
| 连击提升 | 数字弹一次、短句浮现 | 240ms | 不遮挡答案 |
| 章节完成 | 章末印章 + 复盘卡片 | 600–800ms | 可一键跳过 |

遵循 `prefers-reduced-motion`：关闭彩纸、漂浮、页面位移和印章旋转，只保留即时状态变化。动效不能改变布局高度，也不能延迟提交结果。

### 6.4 可选音效

- 默认关闭，首次开启由玩家主动操作。
- 只做界面音效，不做循环 BGM，不自动播放。
- 使用 Web Audio 合成短音，保持单文件零依赖。
- 建议四种：选中轻点、正确双音、错误闷响、章节完成盖章。
- 音量控制在低水平；连续快速点击时合并播放，避免叠音。
- 音效开关独立于动效开关，并持久化偏好。
- 所有音效信息必须有视觉等价物；听不到也不影响完成。

### 6.5 可访问性

- 所有可点击元素使用原生按钮或具备完整键盘行为的角色。
- 选项选中态使用 `aria-pressed` 或等效状态，并提供勾选图标，而不是只用渐变色。
- 反馈容器使用 `aria-live="polite"`，只播报“答对了/还差一个步骤/错在可抵扣增值税”等摘要，不播报整页。
- 详情弹层打开后限制焦点在弹层内；关闭后焦点回到原触发按钮。
- 对话框使用明确标题和说明；背景点击关闭只作为鼠标快捷方式，不能作为唯一关闭方式。
- 输入框有可见标签，错误提示通过描述关系与输入框绑定。
- 焦点样式不能被 `overflow: hidden` 或固定操作条遮住。
- 支持键盘：Tab、Shift+Tab、Enter 提交、Esc 关闭、Space 选择；选项快捷键只在无输入焦点时生效。
- 颜色对比度正文至少 4.5:1；小号辅助文字和按钮也要复核对比度。
- 不只通过颜色区分正确与错误；图标、标题和正文都要表达状态。
- 兼容 200% 缩放；320px 宽度下不出现横向滚动。
- 动画、音效、连击都不应成为理解状态的唯一通道。

## 7. 剧情节奏、梗与激励系统

### 7.1 剧情节拍

每章采用“一个工作现场，一个具体麻烦”的结构：

1. **冷开场**：NPC 把一叠单据、一张报表或一句客户要求推到柚柚面前。
2. **局部冲突**：每一关解决同一个麻烦的一部分，而不是互不相关的知识卡。
3. **业务后果**：答对后出现可感知的结果，例如报表变清楚、凭证盖章、仓库数字对上。
4. **章末收尾**：柚柚用一句话总结自己抓到的规律；王姐只补充一个真正的坑。

建议角色分工：

- 王姐：直接、惜字如金，负责点破规则。
- 仓库老陈：用实物和单据讲话，负责存货、固定资产等场景。
- 销售总监：只关心成交和回款，制造收入确认的冲突。
- 审计姐姐：不吓人，但擅长追问“依据呢”。

每个 NPC 的说话方式要稳定，不能所有人都变成同一个讲梗机器。

### 7.2 防刷题疲劳

- 每 3 关或约 6–8 分钟后，允许插入一张无题“茶水间”小卡：一句角色闲话、一个本章记忆钩子，不能强制阅读。
- 同一题型连续出现不超过 2 关；连续答错两次后，切换到拆解模式。
- 正确反馈不全篇重复知识点；只展示本关判断链，把完整内容留给详解。
- 章末复盘只保留三个问题：抓到了什么、还要看什么、下一章会遇到什么。
- 复习模式不显示“你已失败”，只显示“这关你曾经通过；这次可以只看关键分叉”。

### 7.3 梗的使用

可以用的会计现场梗：

- “借贷必相等，咖啡不一定。”
- “这张专票不是快递单，别顺手塞进成本。”
- “月末结账不是月末惊喜。”
- “数可以慢慢算，科目不能乱牵手。”
- “发票到了不等于收入到了，客户拿到控制权才算。”

使用规则：

- 每关最多 1 个梗；技术解释中最多 1 句记忆钩子。
- 梗不能替代定义，不能让玩家需要先懂梗才懂题。
- 不嘲讽玩家、不嘲笑职业、不使用有时效性且易过期的网络热词。
- 答错文案可以幽默，但必须先给有用信息；幽默句不能占据反馈主体。

### 7.4 连击

- 只有**新关卡首次提交即答对**才增加连击。
- 答错、重试后答对、查看会揭示答案的详解、带练通过都清零连击。
- 连击从 3 开始显示，避免个位数跳动干扰阅读。
- 连击不影响解锁、靠谱值倍率或内容质量；只提供称号、印章或角色反应。
- 建议称号：3 连“手很稳”、5 连“账房定海针”、8 连“王姐放心”。称号可重复获得，但不做永久排行榜。
- 连击中断文案保持轻量：“连击清零，踩坑记录 +1；账还得继续做。”

### 7.5 靠谱值

靠谱值是累计学习进度，不是可消费货币，也永远不扣减。

| 通关方式 | 发放比例 | 连击 | 说明 |
|---|---:|---|---|
| 首次提交即答对 `clean` | 100% 关卡基础值 | +1 | 最理想路径 |
| 查过含答案详解后首次答对 `assisted` | 60% | 清零 | 保留了独立作答，但使用了完整答案支架 |
| 答错后自己改对 `self_corrected` | 60% | 清零 | 仍完整通关 |
| 按解析带练通过 `guided` | 20% | 清零 | 防止卡死，保留学习痕迹 |
| 复习已通关关卡 | 0 | 不变 | 可重复练，不重复刷分 |
| 答案格式错误 | 0 | 不变 | 不计入答题次数 |

关卡基础值继续使用内容中的 `xp`，但最终显示时向上取整到整数。靠谱值只用于累计进度和阶段称号，不能兑换解锁。

### 7.6 踩坑记录

每条踩坑记录至少包含：

- 知识点 ID。
- 错误次数。
- 最近一次错误选项/输入类型。
- 具体误解标签，例如“把可抵扣增值税计入成本”。
- 最近发生时间。
- 是否已在该知识点上重新独立答对。

呈现规则：

- 学习档案只列前 5–8 个“值得回看”的坑，按最近频率和最近时间排序。
- 每条用“人话坑名”，不只列知识点标题。
- 点击进入详解的对应段落，或进入复习模式。
- 再次独立答对后可标记“已填平”，但记录不删除；玩家可以手动清理学习档案。
- 不带羞辱性标签，不使用“屡教不改”“低级错误”等措辞。

### 7.7 章末复盘

章末复盘固定三块：

1. **你抓对的规律**：2–3 条，用本章语言复述。
2. **你最该再看一眼的坑**：最多 1 条，来自真实踩坑记录；没有踩坑则显示易混提醒。
3. **下章预告**：一句剧情钩子，不剧透答案。

复盘页主按钮为“继续下一章”，次按钮为“回看本章”。如果本章还有未通关关卡，不显示“已通关”，而是回到地图并标出缺口。

## 9. 状态清单

### 9.1 路由状态

- 当前页面：首页、科目地图、关卡、知识库、学习档案。
- 当前科目、章节、知识点。
- 返回栈：从详解进入另一知识点时，关闭后回到原关卡。
- 最近学习位置：只保存可恢复的章节/知识点，不保存未提交答案。

### 9.2 玩家进度状态

- 每关通关方式：未通关、`clean`、`assisted`、`self_corrected`、`guided`。
- 每题最佳尝试次数。
- 总靠谱值、当前连击、最高连击。
- 踩坑记录：次数、误解标签、最近时间、是否已填平。
- 章节状态：锁定、可进入、进行中、已通关。
- 科目状态：未开始、进行中、已通关。
- 迁移版本号；旧存档不可因字段缺失被清空。

### 9.3 关卡交互状态

- `phase`：`first_read / answering / wrong_1 / wrong_2 / correct / guided / review`。
- `attempts`。
- `coachLevel`：0、1、2。
- `draft`：按题型分别保存。
- `lastSubmitted`。
- `assisted`。
- `detailOpen`。
- `feedback`：类型、错因 ID、关联选项、下一步动作。
- `scrollAnchor`：反馈出现后应聚焦或滚动到的位置。

### 9.4 设置状态

- 音效开关。
- 动效偏好：跟随系统或手动关闭。
- 字号偏好：标准/大号，作为 P2 可选项。
- 首次玩法提示是否已读。

### 9.5 内容状态

- 内容包 ID、版本、科目、章节顺序。
- 题目校验状态：缺答案、答案 ID 不存在、排序初始顺序即正确、关键词集合为空、分录不平衡等。
- 导入内容与内置内容的合并结果。
- 校验失败时拒绝导入，不覆盖现有内容。

## 10. 关键文案示例

以下示例以“存货初始计量”为同一关，展示一条完整的文案链。

### 10.1 剧情与三件套

**剧情冲突**

> 仓库老陈把三张单子拍在桌上：“买价、运费、装卸费都在这。专票也给你了，下班前算个存货成本，别把税也塞进去。”

**关键词**

`买价` `运输费` `装卸费` `可抵扣增值税`

**这题要你干什么**

> 算出这批原材料的入账成本，可抵扣增值税不计入。

**原题**

> 采购原材料一批，买价 100,000 元，发生运输费 2,000 元、装卸费 500 元，取得可抵扣增值税专用发票注明税额 13,000 元。该批原材料的入账成本是多少元？

**题干翻译**

> 题目问“成本”，不是问一共付了多少钱；买价和让货到库的费用进成本，可抵扣增值税单独走税费。

### 10.2 正确反馈

**标题**

> 对，102,500 元。你把 13,000 元进项税拦在成本外面了。

**判断链**

> 入账成本 = 100,000 + 2,000 + 500 = 102,500 元。  
> 可抵扣增值税记入“应交税费—应交增值税（进项税额）”，不影响存货成本。

**剧情结果**

> 老陈看了一眼数字：“行，这批货终于有自己的身价了。”

### 10.3 第一次答错

**玩家选了 115,500 元时**

> 你算的是“总共付了多少钱”，不是“存货成本”。13,000 元是可抵扣进项税，不进成本。先把税从成本里拿出来，再试一次。

**玩家漏了装卸费时**

> 装卸费不是快递小哥的跑腿费，它是让货到达当前场所和状态的必要支出。漏了它，成本会少算。

### 10.4 第二次答错后的拆解

**标题**

> 先别总算，先分栏：哪些钱让货“到库可用”，哪些钱以后能抵扣。

**拆解**

1. 买价：让货属于你，进成本。
2. 运输费、装卸费：让货到达当前状态，进成本。
3. 可抵扣增值税：单独形成进项税，不进成本。
4. 再把前两项相加，不要拿总付款倒推。

**操作**

> 主按钮：`带着这条路线再算一次`  
> 次按钮：`看完整详解`

### 10.5 详解与带练

**详解首句**

> 存货成本记的是“让货达到现在这个位置和状态所花的钱”，不是“这次一共付出多少钱”。

**带练出口**

> 这次跟着解析走：买价 100,000 + 运费 2,000 + 装卸费 500 = 102,500 元；13,000 元进项税另记。  
> 按钮：`按这条路线带练通过`  
> 辅助说明：`带练通过会解锁下一关，但不计连击，也只发 20% 靠谱值。`

### 10.6 解锁与章末

**单关解锁**

> 下一关已解锁：委托加工物资与消费税。  
> 王姐：“别急着走，下一张单子里还有代收代缴的消费税。”

**章末复盘**

> 本章你抓住了：  
> 1. 存货成本看“达到当前状态的必要支出”。  
> 2. 可抵扣增值税不进成本。  
> 3. 合理损耗不减少总成本，但会抬高单位成本。  
>  
> 最值得再看一眼：你在“可抵扣增值税”上踩过 2 次坑。  
> 下章预告：固定资产买回来只是开始，折旧才是长期剧情。

### 10.7 判断题示例

**题目**

> 判断：谨慎性就是尽量压低利润，多计提准备。

**理由选项**

- 对，因为谨慎性要求不高估资产和收益。
- 错，谨慎性要求不高估资产和收益，但不允许秘密准备。
- 错，因为谨慎性只影响负债。

**答错文案**

> 你抓住了“别高估”，但把谨慎性推成了“故意压低”。谨慎性不是秘密准备；没有依据的多提，反而会破坏可靠性。

### 10.8 找关键词示例

**任务**

> 圈出决定研发支出能否资本化的词。

**词块**

`研究阶段` `开发阶段` `满足资本化条件` `金额较大` `已经申请专利`

**正确集合**

`开发阶段` `满足资本化条件`

**漏选文案**

> “开发阶段”只是入口，还要同时满足资本化条件。两个词少一个，结论都不能成立。

## 11. 内容数据契约

### 11.1 通用字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 全局稳定 ID，推荐 `科目-章节-知识点` |
| `mode` | 是 | 六种题型之一 |
| `title` | 是 | 本关知识点标题 |
| `goal` | 是 | “这题要你干什么” |
| `keywords` | 是 | 2–4 个题干关键词 |
| `translate` | 是 | 常驻题干翻译 |
| `prompt` | 是 | 原题 |
| `explain` | 是 | 正确判断链 |
| `wrongHint` | 是 | 无具体错因数据时的兜底提示 |
| `detailId` | 建议 | 对应知识卡 |
| `xp` | 是 | 基础靠谱值 |
| `misconceptions` | 建议 | 选项/答案到误解标签的映射 |

### 11.2 题型专属字段

| 题型 | 额外字段 | 校验要求 |
|---|---|---|
| 选择 | `options[]`、`answerId` | 3–4 项；答案 ID 必须存在；每项有稳定 ID |
| 数字 | `answer`、`unit`、`tolerance` | 答案有限；单位明确；容差非负 |
| 分录 | `vouchers[]`、`answerId` | 每张凭证行有借贷、科目、金额；借贷平衡或明确说明差额原因 |
| 排序 | `items[]`、`answerOrder[]` | 3–6 项；顺序覆盖所有项；初始展示顺序不等于答案顺序 |
| 关键词 | `tokens[]`、`answerTokenIds[]` | 6–9 个词块；正确集合 2–4 个；至少 2 个干扰词 |
| 判断 | `answerBool`、`reasons[]`、`answerReasonId` | 理由 2–3 个；判断与理由成套；不能只有二选一 |

### 11.3 内容校验红线

- 缺少答案时拒绝导入或构建，禁止默认成 A。
- 答案索引越界、排序答案不完整、关键词答案为空时拒绝导入。
- 重复知识点 ID 时拒绝导入，并指出冲突位置。
- 一个章节少于 2 关时给出警告；同一章节连续 3 关同题型时给出警告。
- 分录借贷不等、数字单位与题干不一致时阻止发布。
- 旧内容迁移只能补默认展示字段，不能补“正确答案”。

## 12. 当前 `LedgerQuest.html` 骨架审阅

### 12.1 已经不错的部分

- 单文件、零外部依赖的技术路线成立。
- 已有科目地图、章节卡、关卡、反馈、知识库、学习档案和详情弹层的基本分区。
- 已有 `choice / number / journal / sort / truefalse` 的显示分支，后续可扩展。
- 已有移动端断点、焦点可见样式和 `prefers-reduced-motion` 基础支持。
- 反馈在关卡内容流内，不是全屏弹窗，符合学习上下文。

### 12.2 P0 问题

1. **内容只有“中级会计实务”一科。**  
   `LedgerQuest.html:1601` 起只向 `SUBJECTS` 推入 `practice` 一个科目；与三科全科目标不一致。经济法、财务管理目前没有可用内容。

2. **没有真正的关卡/章节锁定。**  
   章节卡全部可直接进入，只有完成度文字；`.chapter-status.locked` 实际用于“未完成/进行中”，和“锁定”语义冲突。路线中未完成关卡只是没有 `data-action`，视觉和可访问状态都没有明确“未解锁”说明。

3. **六种题型不完整。**
   - 没有“找关键词”题型的渲染与判分。
   - `journal` 和 `truefalse` 有显示分支，但当前内容没有实际关卡。
   - `truefalse` 直接复用普通选择，无法要求“判断 + 理由”，容易变成 50% 蒙对。
   - 排序题当前按数组原顺序展示，示例中正确顺序就是 `0,1,2,3,4`，玩家只需从左到右点击，没有真正排序。

4. **二次答错没有成为独立状态。**  
   `submitAnswer()` 只累加 `attempts`，`renderFeedback()` 对错误使用同一套通用卡；第二次错误仅因为 `attempts >= 2` 自动展开翻译，没有拆解路线、聚焦第一处错位或带练出口。另一个问题是：无论错几次，首次通关仍发全额 `q.xp`，且没有 `completionKind`。

5. **章节剧情没有真正闭环。**  
   `chapter.outro` 已写入数据但渲染中没有使用；通关最后一关只回地图并弹 Toast。章节没有冷开场、章末复盘和剧情收束，长期会退化成题库。

6. **详解弹层缺少完整键盘与焦点管理。**  
   打开后没有把焦点移入弹层、限制焦点或关闭后恢复；整页重绘还会丢失原焦点。反馈区也没有 `aria-live`，键盘/读屏用户可能不知道提交结果。

### 12.3 P1 问题

7. **固定三件套没有真正固定。**  
   关键词和任务常驻，但“题干翻译”默认折叠，首次尝试时不可见；不满足“关键词 / 这题要你干什么 / 题干翻译”固定展示的要求。

8. **低阅读负担仍不足。**  
   关卡高度被顶栏、章节标题、剧情卡、关键词、任务、原题层层堆叠；手机首屏很可能看不到选项。大量辅助文字只有 9–12px，且多个标签使用大写英文 eyebrow，增加视觉噪音。

9. **移动端操作路径不顺。**  
   手机端侧栏被放到主内容之后，本关路线退化成很靠后的卡片；提交按钮仍在内容流内，长反馈出现后需要反复上下滚动。没有稳定的底部主操作区或反馈聚焦。

10. **内容与进度数据太薄。**  
    当前只记录布尔通关、靠谱值、连击和踩坑次数。没有通关方式、最佳尝试次数、最近误解、时间、带练状态，无法支持学习档案、复盘和防刷设计。

11. **内容数据存在错位。**  
    当前 `p12-t2` 标题是“时段法与时点法”，但 `short / plain / example / question` 写的是民间非营利组织“交换交易收入与非交换交易收入”，内容明显串章。说明目前缺少内容完整性校验。

12. **导入校验不足。**  
    缺答案时 `question.answer` 默认成 `0`，会把坏内容静默变成“选 A”；导入逻辑只做合并，不检查重复 ID、答案越界、排序答案不完整、关键词空集合或分录不平衡。

13. **反馈文案与题型脱节。**  
    错误标题和安慰句来自随机数组，不能指出玩家具体错在哪个选项；正确反馈虽然显示公式和分录，但没有区分“首次答对 / 改对 / 带练通过”。

14. **“小抄”和“知识点详解”实际打开同一内容。**  
    两个并列按钮造成功能重复，也增加选择成本。建议合并为“详解”，或在确有区别时分别定义“30 秒小抄”和“完整详解”。

### 12.4 P2 问题

15. **搜索每次输入都整页重绘。**  
    中文输入法组合输入时存在焦点和光标跳动风险；应局部更新结果区，或至少避开 composition 阶段的重绘。

16. **顶栏统计在手机端失去标签。**  
    小屏隐藏“靠谱值/连击”标签后只剩数字，语义不明；建议压缩为一个进度入口或保留短标签。

17. **彩纸和漂浮动画没有节流。**  
    当前每次正确都生成固定数量彩纸；复习关卡也会触发。应按首次通关、里程碑和节流动画区分，并完整尊重减少动态偏好。

18. **没有音效与偏好持久化。**  
    单文件可合成音效，但当前没有开关、音量控制或持久化偏好。

19. **没有章末复盘与跨科联动入口。**  
    三科目前是独立列表，缺少章节结束后的知识迁移提示，难以支撑“全科理解”而不是三套孤立题库。

## 13. 验收清单

### 13.1 状态流验收

- [ ] 首次答对：发基础靠谱值的 100%，连击 +1，解锁下一关，但停留在正确反馈。
- [ ] 答错一次：不扣靠谱值，显示选项对应的具体错因，可重试或看详解。
- [ ] 答错两次：显示拆解路线，仍保留“再试一次”；详解底部出现带练出口。
- [ ] 看过含答案详解后自己答对：记录 `assisted`，靠谱值为基础值 60%，连击清零。
- [ ] 重试后答对：通关并解锁，记录 `self_corrected`，靠谱值为基础值 60%，连击清零。
- [ ] 带练通过：通关并解锁，记录 `guided`，靠谱值为基础值 20%，连击清零。
- [ ] 答案未选完整：提交按钮禁用或只提示格式，不增加错误次数。
- [ ] 复习已通关关卡：不重复发靠谱值，不把连击刷高。
- [ ] 打开/关闭详解：草稿、错误次数、滚动位置和焦点都保持正确。
- [ ] 最后一关通过：进入章末复盘，不直接回地图。
- [ ] 关闭页面再打开：已通关状态、靠谱值、踩坑记录正确恢复。

### 13.2 布局与可访问性验收

- [ ] 375×667 和 390×844 下无横向滚动。
- [ ] 手机首屏能看到关键词、任务和原题入口，且主操作按钮不被遮挡。
- [ ] 320px 宽、200% 缩放下仍可完成选择并提交。
- [ ] 仅键盘可完成至少一关完整流程。
- [ ] 详情打开后焦点不会跑到背景；Esc 可关闭并回到触发按钮。
- [ ] 正确/错误/选中态不只靠颜色。
- [ ] `prefers-reduced-motion` 下无彩纸、漂浮和大位移。
- [ ] 音效关闭时所有反馈仍有文字与视觉等价物。

### 13.3 内容验收

- [ ] 六种题型各至少有一个真实关卡样例。
- [ ] 排序题初始顺序一定不是答案顺序。
- [ ] 判断题必须同时校验判断和理由。
- [ ] 每关都有 2–4 个关键词、任务句、常驻翻译和针对性错误提示。
- [ ] 内容校验能拦截缺答案、重复 ID、答案越界和分录不平衡。
- [ ] 每章至少有一次剧情收束，不只靠 Toast。

## 14. 实施顺序建议

### 阶段 A：先把闭环做对（P0）

1. 建立通用题型答案契约与内容校验。
2. 重构关卡状态为 `first_read / answering / wrong_1 / wrong_2 / correct / guided / review`。
3. 完成顺序解锁、章节锁定与章末复盘。
4. 固定三件套上移，翻译改为常驻。
5. 补六种题型的真实交互，优先完成关键词、判断题和真正打乱的排序题。
6. 完成移动端提交栏、反馈聚焦、详情焦点管理。
7. 完成二次答错拆解路线和带练出口。

### 阶段 B：让反馈像老师，而不是像判卷机（P1）

1. 为每个干扰项补误解标签与专属错因文案。
2. 按具体误选项细化二次答错文案，并打磨带练页的因果展示。
3. 加入 `completionKind`、靠谱值规则、连击和踩坑记录。
4. 加入章节冷开场与章末复盘。
5. 加可选音效、反馈节流和复习模式。

### 阶段 C：把剧情和全科联动做厚（P2）

1. 给三科补统一但可区分的主线冲突。
2. 增加跨科迁移关，例如“合同履约义务 + 收入确认 + 税务处理”。
3. 增加角色反应、章末印章和更细腻的动效。
4. 加入字号偏好和更完整的键盘快捷键帮助。

## 15. 需要在后续内容制作时守住的三条线

1. **一关只考一个判断。** 读不懂时拆成两关，不把计算、分录和术语识别堆在一起。
2. **错误必须可解释。** 玩家答错后要知道自己错在哪个词、哪一步或哪条分录，不能只收到随机鼓励。
3. **通关可以奖，理解不能被锁死。** 连击和靠谱值奖励独立完成，详解和带练永远为卡关玩家保留出口。
